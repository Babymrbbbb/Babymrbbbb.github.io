01sensenova-gateway · 统一模型调用层

多账号多模型难管理，单 key 限流，AI 一忙就不可用。

一个端点聚合多个模型账号，池化调度、熔断降级与自动切换；零依赖接入可观测性埋点。

02llm-wiki · LLM×RAG 知识库

非结构化资料散落各处时，直接向模型提问容易得到无出处的答案。

raw → wiki → RAG 双轨编译为可导航知识页，配合聚合页回归测试与检索探针；口语化问法由语义兜底，事实型问答可追溯来源。

GitHub ↗

03ai-native-team · Agent 编排

AI 输出没人把关，自产自检容易放水。

按职责拆分 Agent 角色，双模型隔离校验与任务单闭环，执行方与验收方分离。

GitHub ↗

04hunkon_rag · 可复现 RAG 服务

知识库问答要可验证，需要事实护栏、自愈索引和评测闭环。

RAG 服务实现：混合检索 + 交叉编码器精排 + CRAG 自纠错 + 多租户 RBAC + 146 项测试与 CI 评测门禁，可复现。

GitHub ↗

05prompt-craft · 提示词工程

提示词靠感觉写，效果不稳定，无法复用。

按九要素结构组织提示词模板，覆盖跨模态实战与效果评测方法。

GitHub ↗

06kb-cli · 零依赖本地知识库命令行

知识库工具常依赖一整套外部服务，本地跑不起来，检索质量也无从验证。

零依赖命令行实现多子库 × 多层检索，文档解析与召回优先策略均可离线复跑。

GitHub ↗

07rag-vector-vs-keyword · 检索方式对照

「换成向量检索就更准」常被当成默认假设，选方案时缺可复现的实测依据。

32 条带标注查询在同一套评测标准下对照：BM25 Recall@5 0.953、ONNX MiniLM 0.594，结果集重合度仅 0.298，据此给出两路融合而非二选一的适用条件。

GitHub ↗

08langchain-kb-qa · 检索增强问答服务

检索对照的结论停在报告里，没有落到能部署、能调用的服务。

LangChain LCEL + chromadb + 中文二元组 BM25 混合检索，FastAPI /api/ask、单页 UI、Docker，离线可跑且编码器可插拔自动降级。

GitHub ↗

09lora-finetune-demo · 参数高效微调对照

LoRA 省参数常被当结论引用，但 ΔW=B·A 怎么起作用、究竟省多少说不清。

零依赖手写前向与反向，全量 280 参数 vs LoRA(r=2) 108 参数（38.6%），在构造的小型分类任务上两者准确率均 100%；附 PEFT 生产模板。
